# Videoflow 产品与开发文档

本文档集描述 AI 视频创作工作区的第一阶段产品范围、稳定接口和模块边界。原型图仅用于表达布局与交互意图，不作为像素级视觉规范。

## 阅读顺序

1. [产品需求文档](./product-requirements.md)：术语、范围、交互、状态规则和验收标准。
2. [产品接口文档](./product-api.md)：领域对象、HTTP API、AI 工具契约、错误和并发规则。
3. [功能模块与多 Agent 开发计划](./modules-and-agent-plan.md)：架构边界、模块职责、依赖图、并行/串行安排和交付门禁。
4. [现有 AgentRuntime 接口](./runtime-api.md)：当前已经实现的会话、事件和 SSE 接口。

机器可读契约位于 [openapi.json](./openapi.json)。前端运行 `pnpm contract:generate` 生成类型，运行 `pnpm contract:check` 检查契约与生成文件是否漂移。

## 实施状态

Wave 0 已完成：

- OpenAPI 3.1 契约包含 27 个路径、43 个操作和 60 个共享 schema。
- 零依赖生成器输出 `web/src/productApi/generated.ts`，前端构建会检查漂移。
- 服务端产品域、应用端口、基础设施和 API 挂载点已经建立，并与 AgentRuntime 分离。
- SQLite v1 迁移包含项目、分镜、脚本、资产、媒体、提案、生成任务、线程绑定、outbox 和幂等记录。
- 数据库测试覆盖空库升级/回滚、资产按引用复用、跨项目引用拦截和两级分区约束。

Wave 1 Agent A（分镜与脚本）已完成：

- 项目、分镜目录和脚本 API 已接入 SQLite，不返回占位数据。
- 分镜支持创建、重命名、重排、软删除与恢复，并保证项目至少保留一个活动分镜。
- 分镜列表支持 `anchorId + before/after` 窗口，响应包含全局 `anchorIndex`，也支持游标翻页。
- 写入使用 `expectedRevision` 防止静默覆盖；创建、重排和恢复使用 24 小时幂等记录。
- 仓储和 HTTP 测试覆盖 200 个分镜的锚点定位、修订冲突、项目作用域、幂等重放及统一错误响应。

Wave 1 Agent B（资产库、分区与引用）已完成：

- 项目共享资产、可扩展视图、两级分区和分镜资产引用均已接入 SQLite 与 HTTP API。
- 复制资产使用单事务“引用复制”：复用资产和媒体 ID，只创建目标分镜的分区与引用；重复资产按 `skip` 报告。
- 写操作支持修订冲突、24 小时幂等重放、项目/分镜作用域校验和 outbox 事件。
- 被引用资产禁止删除；删除非空分区必须明确选择移动引用或解除引用。
- 端到端测试覆盖创建、幂等重放、跨分镜复制、共享资产不重复和在用资产删除保护。

Wave 2 Agent B（资产前端）已完成独立模块交付：

- 两级资产分区树、共享资产类型/关键词筛选、分页多选和已绑定状态均已实现。
- 跨分镜复制只提交引用复制请求，并明确展示新增/重复跳过结果，不暗示复制文件。
- 资产卡支持选中状态和带文字的待确认徽标；切换筛选或分镜时会隔离过期响应。
- 模块经由 `AssetWorkspaceClient` 组合，尚未改动 `App.tsx`；页面接线由串行集成阶段完成。

Wave 3 Agent B（提案 UI）已完成独立模块交付：

- 提案目标支持黄色待确认、橙色冲突边界和键盘可访问的文字徽标。
- 详情面板展示正式内容与 AI 建议的行级差异，并提供确认/取消操作。
- 确认携带提案与目标修订号；网络不明确时复用幂等键，版本冲突时禁止直接覆盖。
- 提示词确认成功后可展示生成任务状态；未配置供应商时明确显示等待生成能力。
- 资产与提案模块场景测试、TypeScript 契约检查和生产构建均通过。

Wave 2 Agent D（会话提取与分镜绑定）已完成：

- 会话组件已从单体 `App.tsx` 提取到 `web/src/chat/`，工作区只通过窄作用域属性接入右侧面板。
- 每个 Runtime 线程在服务端绑定唯一项目与分镜；切换分镜会恢复最近线程，新建会话会形成新绑定。
- 服务端在创建线程前校验项目/分镜，并以幂等键防止重试重复绑定；快速切换会取消过期前端请求。
- 消息发送前由服务端依据 `threadId` 读取脚本、资产与媒体摘要；这些内容以 `Data + Turn` 语义注入，文本字段不能提升为指令。

Wave 3 Agent D（验收自动化）已完成：

- `--fixture` 提供 200 个确定性分镜、共享资产、脚本和媒体；浏览器长列表验收固定定位第 137 个分镜。
- 六个关键验收场景由真实 SQLite/HTTP 事务测试与 Playwright 浏览器测试共同覆盖。
- 额外浏览器场景验证分镜之间会话隔离，以及返回原分镜后恢复原线程。
- 统一命令为 `cd web && pnpm test:acceptance`；场景映射见 `web/e2e/README.md`。

其余工作包继续按多 Agent 计划推进；跨模块路由、工具注册和样式整合仍需在最终集成门禁中统一复核。

## 本轮已冻结的关键决策

- 分镜是项目内有序的独立工作区；脚本、关键帧和生成视频属于分镜。
- 资产是项目级共享实体，分镜通过“资产引用”使用它；复制分镜资产只复制引用，不复制资产记录或媒体文件。
- 分镜内修改共享资产的提示词采用写时分叉语义，默认不会静默影响其他分镜。
- AI 只能创建变更提案，不能直接修改正式数据。提案必须由用户确认或取消。
- 图片和视频在当前阶段只做预览，不做裁剪、涂抹、时间线等编辑器能力。
- 产品域与 AgentRuntime 解耦；AI 工具通过产品应用服务创建提案，不能直接写数据库。

## 尚需产品确认但不阻塞第一阶段的事项

- 团队协作、角色权限和审核流；第一阶段按单项目编辑者设计，但服务端仍校验项目作用域。
- 实际图片/视频生成供应商、额度、计费和失败重试策略；接口中保留生成任务抽象。
- 删除共享资产时是否允许强制解除全部引用；第一阶段默认“被引用时禁止删除”。
- 一个项目的分镜、资产与媒体数量上限；第一阶段接口均按可分页和可虚拟列表设计。
