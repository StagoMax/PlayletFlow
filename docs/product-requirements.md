# Videoflow 分镜工作区产品需求文档

状态：第一阶段基线  
版本：1.0  
更新时间：2026-09-26

## 1. 产品目标

Videoflow 为 AI 视频创作提供以“分镜”为中心的工作区。用户在同一页面中完成分镜切换、脚本查看与修改、共享资产组织、关键帧和历史视频预览，并通过右侧 AI 对话提出修改要求。

第一阶段的核心不是图片或视频编辑器，而是建立可信的内容组织与确认机制：AI 可以建议变更，但任何影响脚本、提示词或重新生成的操作，都必须经过用户在对应内容位置确认。

### 1.1 成功标准

- 用户能在不离开工作区的情况下定位任意分镜及其脚本、资产、关键帧和历史视频。
- 同一资产能被多个分镜复用，存储层只有一份资产和媒体文件。
- 用户能明确区分正式内容、AI 待确认内容和冲突内容。
- AI 不能绕过确认流程直接覆盖正式内容。
- 前后端、媒体能力与 AI 能力可以按稳定契约并行开发。

## 2. 范围

### 2.1 第一阶段必须交付

- 单个项目内的分镜列表、创建、重命名、排序、删除和切换。
- 创建分镜时可选择从已有分镜复用全部或部分资产。
- 分镜脚本展示与人工修改。
- 可新建、重命名、排序和删除的资产分区，支持有限层级。
- 人物、场景、道具和自定义类型资产的选择与添加。
- 共享资产库和分镜资产引用模型。
- 分镜关键帧、生成视频和资产媒体的缩略图、悬停预览、点击详情与主预览。
- 右侧 AI 对话面板接入现有 AgentRuntime。
- 脚本与图片/视频提示词的 AI 变更提案、确认、取消、冲突提示。
- 用户可以在媒体预览中直接编辑并发送提示词；提示词更新与重新生成任务必须原子提交。没有配置生成供应商时显示“等待生成能力”，但不能丢失已确认内容。

### 2.2 第一阶段不包含

- 图片裁剪、蒙版、局部重绘、图层、画布等编辑器。
- 视频时间线、剪辑、转场、字幕、调色和音轨编辑。
- 多人实时协同、评论、审批人角色和细粒度权限 UI。
- 资产自动识别、跨项目资产市场或素材版权管理。
- 特定图片/视频模型供应商的实现细节。

## 3. 术语与领域边界

| 术语 | 定义 | 归属与生命周期 |
| --- | --- | --- |
| 项目 `Project` | 一部视频作品的顶层容器。 | 包含分镜、共享资产库和会话绑定。 |
| 分镜 `Storyboard` | 一个 AI 生成视频片段的工作区，不只是一个画面。 | 属于项目；拥有脚本、媒体和资产引用。 |
| 资产分区 `AssetSection` | 左侧用于组织资产引用的可排序分组，可有父分区。 | 属于某个分镜；删除不删除共享资产。 |
| 共享资产 `Asset` | 人物、场景、道具或自定义创作实体。 | 属于项目；可被多个分镜引用。 |
| 资产引用 `AssetBinding` | 分镜对共享资产的使用关系。 | 属于分镜；保存所在分区、顺序和分镜级覆盖信息。 |
| 媒体项 `MediaItem` | 图片或视频及其元数据、比例、提示词和生成来源。 | 资产媒体可共享；关键帧和生成视频属于分镜。 |
| 变更提案 `ChangeProposal` | AI 对某一字段提出的、尚未生效的修改。 | 确认后才写入正式数据；可取消、冲突或过期。 |
| 生成任务 `GenerationJob` | 根据已确认提示词生成媒体的异步任务。 | 与目标和目标修订号绑定，可重试但不能重复提交。 |

### 3.1 共享与私有规则

| 内容 | 是否可跨分镜共享 | 复制分镜资产时的行为 |
| --- | --- | --- |
| 共享资产记录 | 是 | 不复制，只复用同一个 `assetId`。 |
| 资产源媒体文件 | 是 | 不复制二进制文件，只复用媒体引用。 |
| 资产分区结构 | 否 | 在目标分镜创建等价分区。 |
| 资产引用及排序 | 否 | 在目标分镜创建新引用，仍指向原资产。 |
| 分镜脚本 | 否 | 默认不复制；“复制整个分镜”未来另行定义。 |
| 分镜关键帧 | 否 | 不复制。 |
| 分镜生成视频 | 否 | 不复制。 |
| 分镜级提示词覆盖 | 否 | 默认不复制，除非复制对话框明确勾选。 |

当用户在某个分镜内修改复用资产的提示词时，系统默认创建分镜级覆盖并在确认后生成该分镜的派生媒体，原共享资产和其他分镜保持不变。未来若提供“修改共享资产”入口，必须列出受影响分镜并二次确认。

## 4. 信息架构与布局

页面分为三列：

1. 左侧内容导航：分镜下拉菜单、脚本分区、资产分区、视频分区。
2. 中间预览区：左上信息卡和主媒体预览；第一阶段只有查看能力。
3. 右侧 AI 对话区：当前分镜的会话、工具活动和变更提案摘要。

桌面端优先。建议左列宽度 280–360 px，右列宽度 360–440 px，中间区域占用剩余空间。窗口不足时允许左右面板折叠；不在第一阶段承诺完整移动端体验。

## 5. 用户故事与详细需求

### 5.1 分镜选择与管理

#### US-SB-01 切换分镜

用户点击左上角“分镜 N”打开菜单。菜单打开后必须把当前分镜滚动到可视区域，并尽量定位在菜单中央，而不是总从列表顶部开始。

验收标准：

- 当前分镜有选中标记，并设置 `aria-current`。
- 菜单支持鼠标、方向键、Home、End、Enter 和 Escape。
- 切换分镜后，脚本、资产、视频、主预览、待确认提案和右侧会话上下文全部切换到目标分镜。
- 若当前分镜有未提交的人工表单，切换前提示保存或放弃；AI 提案已经持久化，不阻止切换。
- 列表较长时使用虚拟列表，仍能依据分镜顺序索引定位当前项。

#### US-SB-02 新建分镜

用户可创建空白分镜，也可从一个已有分镜复用资产。

验收标准：

- 新分镜插入到当前分镜之后，后续可拖拽排序。
- 名称采用可编辑的默认值，如“分镜 12”，服务端保证项目内显示名不必唯一但 ID 唯一。
- 选择复用资产时，只复制分区结构和资产引用，不复制共享资产或文件。
- 创建成功后自动切换到新分镜；失败时保留当前工作区。

#### US-SB-03 删除分镜

- 删除前显示该分镜包含的脚本、关键帧、视频和待确认提案数量。
- 删除采用软删除；默认可在 30 天内恢复，具体清理周期可配置。
- 只删除该分镜的私有内容和资产引用，不删除共享资产或被其他分镜引用的文件。
- 若删除的是当前分镜，成功后切换到相邻分镜；项目至少保留一个分镜，最后一个分镜只能清空或由系统立即补建空白分镜。

#### US-SB-04 复制资产引用

- 用户可选择全部分区/资产，或仅选择部分引用复制到目标分镜。
- 目标已有相同 `assetId` 时默认跳过并报告；可选择移动到指定分区，但不产生重复引用。
- 操作结果明确显示“新增、跳过、失败”数量。

### 5.2 脚本分区

#### US-SC-01 查看与人工编辑脚本

- 左侧显示当前分镜脚本摘要；点击后在中间信息卡显示完整脚本和修改时间。
- 人工编辑保存使用乐观并发控制。若服务端版本已变化，禁止静默覆盖并展示差异。
- 空脚本提供明确空状态和“添加脚本”入口。

#### US-SC-02 AI 脚本提案

- AI 调用脚本修改工具时，只创建提案。
- 左侧脚本区域显示黄色待确认状态，并提供“查看、确认、取消”。
- 查看提案时展示当前文本与建议文本的差异。
- 确认时检查提案所基于的脚本修订号；已被人工或其他提案改动时进入冲突状态，由用户重新选择。
- 取消仅拒绝提案，不改动正式脚本。

### 5.3 资产分区与共享资产

#### US-AS-01 管理资产分区

- 用户可新建、重命名、排序、折叠和删除资产分区。
- 内置建议类型为人物、场景、道具；允许自定义名称和类型。
- 支持父子分区以表达“人物 / 面部”“人物 / 服装”等结构，第一阶段最多两级，防止导航无限嵌套。
- 删除非空分区时，用户选择将引用移动到其他分区或仅解除当前分镜引用；共享资产不被删除。

#### US-AS-02 添加资产

“添加资产”打开选择窗口，先按类型快速筛选，再执行以下任一操作：

- 从项目共享资产库选择已有资产；
- 新建资产并添加已有媒体；
- 创建仅含名称和提示词的占位资产，稍后生成或上传媒体。

弹窗必须显示类型、名称、缩略图、已被多少分镜使用，并支持搜索和多选。添加成功后创建资产引用并出现在当前分区。

#### US-AS-03 资产视图

- 人物可以拥有面部三视图、服装三视图等媒体项。
- 场景可以拥有正视图、俯视图、侧视图等媒体项。
- 道具和自定义资产可以拥有任意命名的视图。
- 视图类型是可扩展元数据，不应通过固定数据库列实现。

### 5.4 视频分区

#### US-VD-01 分镜关键帧

- 支持首帧、尾帧、关键帧和自定义帧类型。
- 每个媒体项显示方形缩略图，但原始宽高比元数据必须保留。
- 关键帧属于当前分镜，不随资产引用复制。

#### US-VD-02 历史生成视频

- 显示当前分镜曾经生成的视频，按创建时间倒序，可查看状态、时长、分辨率、提示词和来源任务。
- 失败中的任务显示失败原因和重试入口；处理中显示进度或阶段，不伪造百分比。
- 默认只读预览，不提供剪辑能力。

### 5.5 缩略图、悬停预览与主预览

#### US-PV-01 方形缩略图

- 左侧所有媒体使用一致的方形容器。
- 图片使用 `object-fit: cover` 生成缩略图；不得用缩略图替代主预览源。
- 视频使用海报帧，并显示视频标记和时长。
- 加载、失败、无媒体均有可辨识占位状态。

#### US-PV-02 悬停大预览

- 鼠标稳定悬停 250–400 ms 后，在缩略图右侧显示大预览浮层；离开有短暂容错延时，避免闪烁。
- 浮层优先出现在缩略图右侧，空间不足时翻转到左侧或限制在视口内。
- 使用 `object-fit: contain` 按正确比例完整显示，不能裁切。
- 键盘聚焦触发同等预览；触摸设备通过首次点击选中，不依赖 hover。
- 视频悬停预览默认静音、循环，遵守减少动态效果设置；失败时退回海报帧。

#### US-PV-03 点击查看详情

点击缩略图后：

- 中间区域主预览显示该图片或视频；视频提供播放、暂停、进度和音量等原生预览控制。
- 左上信息卡显示资产/媒体名称、类型、尺寸、比例、创建时间、生成提示词（若有）和生成状态。
- 当前选中项有清晰选中边框；有待确认提案时使用黄色边框和徽标，但不能只靠颜色表达。
- 切换分镜后若原选中项不存在，则选中该分镜的第一个可预览项；没有媒体时显示空状态。

### 5.6 AI 对话与安全变更

#### US-AI-01 分镜作用域对话

- 每个 AI 会话在服务端绑定项目和分镜；切换分镜加载对应会话。
- 服务端从会话绑定推导工具作用域，模型参数不能自行指定任意项目或分镜 ID。
- AI 可以读取当前分镜摘要及被授权的资产元数据，但媒体原文件只通过受控引用访问。

#### US-AI-02 AI 工具

第一阶段暴露以下产品工具：

- `propose_script_change`：提出完整脚本或文本补丁。
- `propose_media_prompt_change`：提出图片或视频媒体项的提示词修改。

工具执行成功只代表提案已保存，不代表正式内容已更改。工具结果必须返回提案 ID、目标摘要、状态和需要用户确认的提示。

#### US-AI-03 确认、取消和重新生成

提案状态机：

```text
pending ──确认且版本匹配──> applying ──事务成功──> applied
   │                              └─失败──> pending / failed
   ├──取消──> rejected
   ├──目标被改动──> conflicted
   └──目标被删除或超时──> expired
```

- 脚本提案确认后更新脚本，不触发媒体生成。
- 图片/视频提示词可由用户直接发送或通过提案确认；两种入口都要事务性更新目标提示词并写入生成任务/outbox 事件。
- 同一确认请求重试不得创建多个生成任务。
- 生成失败不回滚已确认提示词；用户可以基于同一修订重试生成。
- `pending` 和 `conflicted` 在左侧对应内容以及中间信息卡都可发现。

## 6. 全局状态与反馈

| 状态 | UI 表现 | 允许操作 |
| --- | --- | --- |
| 正常 | 默认边框 | 查看、人工编辑、请求 AI 修改。 |
| AI 待确认 | 黄色边框、徽标、确认/取消按钮 | 查看差异、确认、取消；不覆盖正式值。 |
| 冲突 | 橙色/红色提示和冲突原因 | 刷新基线、重新发起提案、取消。 |
| 生成中 | 进度阶段和停止/重试策略提示 | 查看其他内容；不重复提交。 |
| 生成失败 | 错误摘要、重试按钮 | 重试或修改提示词。 |
| 已删除/失效 | 禁用项或从列表移除 | 关闭详情，必要时恢复分镜。 |

网络失败时，服务端未确认的正式变更不得在 UI 中显示为已保存。人工表单可以保留本地草稿；AI 提案必须以服务端状态为准。

## 7. 非功能需求

### 7.1 性能

- 首次打开工作区在普通宽带下应优先显示骨架和基本元数据，媒体按需加载。
- 分镜菜单、资产选择器和媒体列表支持至少 1,000 项的虚拟滚动或分页。
- 缩略图使用派生尺寸和懒加载；主预览按可视尺寸选择资源，不下载原始大文件作为缩略图。
- 切换分镜时取消过期请求，后返回的响应不得覆盖新分镜状态。

### 7.2 一致性与并发

- 可编辑实体带单调递增 `revision`。
- 修改和提案应用必须提交 `expectedRevision`；不匹配返回 409。
- 创建、复制、应用提案和创建生成任务支持幂等键。
- 共享资产删除前检查引用，默认返回 409 而不是级联删除。

### 7.3 安全

- 所有项目资源必须按已认证成员身份校验；不能仅相信 URL 中的项目 ID。
- 媒体通过短期签名 URL 或同源受控端点访问，不把对象存储永久凭据暴露给浏览器。
- AI 工具作用域由服务端会话绑定决定；输入做 schema 校验、长度限制和审计记录。
- 提示词与脚本按不可信文本渲染，Markdown 禁止任意 HTML/脚本。

### 7.4 可访问性

- 所有菜单、分区、缩略图、对话和确认操作可使用键盘。
- 待确认、错误和选中状态同时使用图标/文字，不只使用颜色。
- 图片有可用替代文本，视频预览控件有可访问名称。
- 浮层不遮挡键盘焦点，并在 Escape 时关闭。

### 7.5 可观测性

- 每个请求携带 `requestId`；生成链路额外携带 `generationJobId`，仅 AI 提案入口再携带 `turnId` 与 `proposalId`。
- 记录提案创建、确认、取消、冲突和生成状态变更，但不在普通日志中写入完整敏感提示词或媒体 URL。

## 8. 关键验收场景

### AC-01 资产引用复制不重复文件

1. 分镜 A 引用人物资产 X，X 有三张媒体。
2. 用户把 X 复制到分镜 B。
3. B 出现新的资产引用，引用同一个 `assetId`。
4. 资产表和媒体对象数量不增加；删除 B 只删除 B 的引用。

### AC-02 下拉定位当前分镜

1. 项目有 200 个分镜，当前为第 137 个。
2. 打开分镜菜单。
3. 第 137 个分镜立即处于可视范围并被标记，用户无需从顶部滚动。

### AC-03 AI 不能直接修改脚本

1. 脚本修订号为 7。
2. AI 工具提出脚本修改。
3. 正式脚本仍是修订号 7，左侧显示待确认。
4. 用户取消后脚本不变，提案状态为 `rejected`。

### AC-04 冲突阻止静默覆盖

1. AI 提案基于脚本修订号 7。
2. 用户人工修改脚本，使修订号变为 8。
3. 用户确认旧提案。
4. 服务端返回 409，提案变为 `conflicted`，修订号 8 的脚本不被覆盖。

### AC-05 提示词确认只生成一次

1. AI 对关键帧 K 创建提示词提案 P。
2. 用户确认 P，网络超时后客户端重试相同请求。
3. P 最终为 `applied`，K 修订号只增加一次，只存在一个对应生成任务。

### AC-06 正确比例预览
