# Videoflow UI 规范

这份规范服务于创作工作区、媒体预览、资产管理和 AI 对话。经确认的界面示例是 [`ui-style-preview.html`](ui-style-preview.html)；应用中的颜色和尺寸以 [`web/src/ui/tokens.css`](../web/src/ui/tokens.css) 与 [`web/src/ui/primitives.css`](../web/src/ui/primitives.css) 为准。

## 1. 视觉方向

- **定位**：专业、简约的 AI 视频创作工具。界面克制、清晰，内容和操作结果优先。
- **主题**：近黑背景与中性炭灰表面。蓝色只用于当前选择、可定位的强调、辅助操作和键盘焦点；主要提交操作使用浅色按钮。
- **边界**：无边框优先。用留白、背景层次和淡阴影区分区域；输入框、弹窗等需要明确轮廓时使用低对比度细边框。悬停改变背景色，不突然出现强调色边框。
- **形状**：使用统一的圆角层级。相邻控件的高度、字号、图标和间距保持协调，避免一个元素特别大、旁边的元素特别小。
- **节奏**：工作区采用适中的信息密度。界面整洁、整齐；主要操作、表单和弹窗留出足够的点击空间。
- **表达**：动效只说明状态变化和空间关系；媒体内容本身是视觉主角。界面不依赖节点画布。
- **信息**：只显示帮助当前决策或操作的信息。相同含义的标题、说明和状态不重复表达；次要细节按需展开。

这是一套工作界面规范，不是营销页面视觉模板。新增视觉效果应服务于内容层级或操作反馈。

## 2. 设计变量

所有跨模块共享的颜色、间距、圆角、控件高度和动效时长都定义在 `tokens.css`。组件样式引用变量，不重复写相同的原始色值。

| 基础色 | 值 | 用途 |
| --- | --- | --- |
| 近黑 `--bg` | `#0d0d0e` | 工作区与导航底色 |
| 炭灰 `--panel` | `#19191a` | AI 助手等容器 |
| 卡片 `--panel-raised` | `#252527` | 卡片、选项与浮层的次级表面 |
| 悬停 `--surface-control-hover` | `#323235` | 无边框控件的悬停反馈 |
| 蓝色 `--accent` | `#1b9ff1` | 小面积强调与选择标记 |
| 浅色 `--action-primary` | `#f0f0f1` | 主要提交操作 |

| 类别 | 变量 | 用途 |
| --- | --- | --- |
| 背景 | `--bg`、`--panel`、`--panel-soft`、`--panel-raised`、`--surface-overlay`、`--surface-canvas`、`--surface-media`、`--surface-composer`、`--surface-composer-focus` | 工作区、侧栏、媒体预览、输入区和弹窗的层次 |
| 边界 | `--line`、`--line-subtle`、`--shadow-control`、`--shadow-surface`、`--shadow-overlay` | 轻分隔线与柔和的层次阴影 |
| 滚动条 | `--scrollbar-thumb`、`--scrollbar-thumb-hover` | 全局细轨样式与悬停反馈 |
| 文字 | `--text`、`--text-secondary`、`--text-muted` | 正文、辅助信息、低优先级说明 |
| 操作 | `--accent`、`--accent-soft`、`--accent-action`、`--action-primary`、`--action-primary-hover`、`--text-on-primary`、`--focus-ring` | 选择、AI 建议应用、主要操作与焦点 |
| 状态 | `--positive`、`--warning`、`--danger` | 成功、待处理或冲突、错误 |
| 字体与尺寸 | `--font-size-*`、`--space-*`、`--radius-*`、`--control-height` | 统一字阶、间距、圆角和控件比例 |
| 动效 | `--motion-fast`、`--motion-standard` | 悬停和状态转换 |

间距优先使用 4、8、12、16、24、32 px。控件圆角约 9 px，较大的卡片和弹窗使用 12–16 px，AI 助手可使用 20 px。共享控件默认高 40 px；粗指针设备提升至至少 44 px。同一操作组里的控件对齐高度和基线。媒体预览尺寸按内容比例定义。

文字默认使用 Inter、Segoe UI、微软雅黑的系统回退。正文和按钮为 14 px，标签和辅助说明为 13 px，弹窗标题为 18 px，页面标题为 24 px；12 px 只用于非关键的短标签或元数据。正文使用一致的行高与字重，重要信息不能依赖小字来塞入界面。

## 3. 共享控件

`primitives.css` 提供样式配方，保留原生 HTML 的语义和行为。组件实现时直接组合下列类名；只有出现跨场景共享的行为时，再提取 React 组件。

| 控件 | 类名与规则 |
| --- | --- |
| 按钮 | `ui-button` 为无可见边框的次级操作，悬停只改变背景；主要操作加 `ui-button--primary`；低强调操作加 `ui-button--quiet`；图标按钮加 `ui-button--icon` 并提供可访问名称。每个操作区通常只保留一个主要按钮。 |
| 表单 | `ui-field` 包含可见的 `ui-field__label` 与 `ui-input`。输入框使用浅边框，不在悬停时增加边框强调。错误使用 `aria-invalid`、关联的说明 ID 和 `ui-field__error`。 |
| 弹窗 | 原生 `<dialog>` 使用 `ui-dialog`，内部使用 `ui-dialog__content`、`ui-dialog__header`、`ui-dialog__title`、`ui-dialog__description`、`ui-dialog__actions`。支持 Esc 关闭；提交中是否允许关闭由业务决定。 |
| 状态标签 | 无边框的 `ui-badge` 搭配 `data-tone="pending|success|error|neutral"`。标签文字必须说明状态，不能只靠颜色。 |

[`CreateStoryboardDialog.tsx`](../web/src/storyboards/CreateStoryboardDialog.tsx) 与 [`DeleteStoryboardDialog.tsx`](../web/src/storyboards/DeleteStoryboardDialog.tsx) 展示了片段表单及危险操作确认。删除对话框在提交前列出受影响的脚本、关键帧、视频和待确认提案；提交期间禁用重复操作，并在对话框内显示错误。

## 4. 状态与交互

| 状态 | 视觉与文案要求 |
| --- | --- |
| 当前选择 | 使用中性灰背景和小面积蓝色标记；键盘焦点使用可见的蓝色轮廓。多选、当前片段、键盘焦点要能区分。 |
| AI 待确认 | 使用暖黄色，并显示“待确认”等文字；未经确认的内容不能表现为已保存。 |
| 处理中 | 显示正在执行的动作和可理解的进度或等待文案；避免控件突然消失。 |
| 成功 | 使用绿色提示与完成文案，指出结果所在位置。 |
| 错误或冲突 | 使用红色或暖色文字、浅背景，必要时增加边界；说明原因和下一步操作，冲突不可覆盖已有内容。 |
| 云端同步失败 | 工作区顶部显示可访问的错误提示；保留本地草稿和待同步标记，版本冲突说明需要备份或人工处理。 |
| 空状态 | 说明当前为什么为空，以及可执行的下一步。 |

悬停、按下、禁用和焦点状态必须分明。键盘焦点保持可见；图标按钮有 `aria-label`；触摸设备不能依赖悬停才能发现主要操作。尊重 `prefers-reduced-motion`。

## 5. 布局与媒体

- 工作区沿用“导航、内容区、AI 助手”的结构。内容拥有最高视觉优先级；辅助信息不与媒体预览争夺注意力。不增加节点画布。
- 桌面端 AI 助手展开时保持稳定宽度和轻量浮层外观，允许折叠为窄入口，内容区使用腾出的空间；展开后保留原会话内容。
- 相同层级的卡片使用相同的尺寸比例、间距、圆角和标题关系。页面内先用留白和背景建立分组，需要时再加轻边框或淡阴影。
- 标题、说明、状态与操作各司其职。已在标题中清楚表达的信息不再用标签重复；仅供排查的 ID、版本号和技术细节放在详情中。
- 响应式调整保留主要任务路径。窄屏可把侧栏和助手区顺序堆叠，但关键操作和状态必须可见、可触达。
- 媒体保留原始比例；占位、加载和失败状态占据稳定区域，减少布局跳动。

## 6. 新界面的检查清单

1. 是否复用了现有变量和控件配方？新增变量是否具有跨场景的意义？
2. 主要操作、状态文字、错误恢复路径是否一眼能找到？
3. 是否有重复说明、非必要状态或过小文字？相邻控件的尺寸比例是否协调？
4. 键盘、触摸和窄屏能否完成同一关键任务？
5. 正文与背景对比度是否达到 WCAG AA 的 4.5:1；焦点是否清楚可见？
6. 是否在正常、悬停、焦点、禁用、加载、错误、空状态下检查过？
7. 是否在实际工作区中与相邻模块并排检查过，而不只看独立组件？

## 7. 维护方式

新增跨模块样式时，先更新 `tokens.css` 或 `primitives.css`，并在本文件补充使用场景。只属于某个功能的布局留在该功能模块。保持交互与业务语义，避免再次在模块里复制灰阶与蓝色的原始色值。
